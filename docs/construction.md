# 建造力系统设计

> 状态：**已实现（第一步 + 第二步均已落地）**。
> 本文是实现依据；`docs/spec.md` §9 是 TS ↔ GDScript 对拍用的公式契约。
> TS：`src/engine/systems/investment.ts` / `labor.ts` / `finance.ts`；
> GDScript：`godot/scripts/sim/sim_core.gd`。

## 一、核心概念

```
建造力 = 每日施工产能（速率，不是库存）

  每日产能 = 失业人口 × 1.0
           + Σ(建筑工坊工人 × 2.5 × (0.6 + 0.4 × 熟练度/100))

  一个工程需要「n 建造力」= n 个"人·天"
  工期 = 需求量 ÷ 每日产能（产能逐日投入，不用完就浪费）
  多个工程 → 一条先进先出队列，串行
```

**建造力不进库存。** 每天重新产生，当天没用完就作废（不结转）。
因此不存在"攒一堆建造力一口气开工"，扩张只受**时间 × 产能**限制。

## 二、产能

| 来源 | 每日建造力 |
|---|---|
| 失业人口（上工地） | **1.0**（固定，不随熟练度变 —— 非熟练工） |
| 建筑工坊工人 | **2.5 × (0.6 + 0.4 × 熟练度/100)** |

| 熟练度 | 建筑工坊工人 |
|---|---|
| 30（居民起步） | 1.8 |
| 50（新工坊默认） | **2.0** ← 正好是失业人口的 2 倍 |
| 100（满级） | 2.5 |

- **不封顶**：有多少失业人口就有多少产能
- 熟练度曲线**沿用产量那条** `0.6 + 0.4 × 熟练度/100`（`production.ts:57` / `sim_core.gd:336`），
  不引入第二套熟练度语义
- 基数取 2.5 的理由：新工坊默认熟练度 50 时曲线值为 0.8，`2.5 × 0.8 = 2.0` 精确对上"一人顶两人"

## 三、工时需求

| 类别 | 建筑 | 建造力 |
|---|---|---|
| **采集**（11） | 农场 / 伐木场 / 采石场 / 粘土坑 / 狩猎营地 / 渔场 | **12** |
| **加工 · 穷人级**（4） | 粗面粉磨坊、粗面包房、木柴坊、砖窑 | **12** |
| **加工 · 中产级**（10） | 精面粉磨坊、白面包房、粗织坊、粗布衣坊、细织坊、常服坊、陶器坊、熏鱼坊、肉干坊、**建筑工坊** | **24** |
| **加工 · 富人级**（6） | 糕点房、**糖坊**、瓷窑、家政工坊、华服坊、皮衣坊 | **36** |
| **大型**（2） | 剧院、住房坊 | **48** |
| **住房** | 茅屋 / 木屋 / 砖房 | **12 / 24 / 36** |
| **升级** | 每 +1 级 | **24 × 当前等级** |

分级规则：**该建筑产出最终被哪个（最低）阶层消费**（含缺货替代链）。
「建筑工坊」的产出是建造力本身、不属于任何阶层，按**中等规模**归 24。

**12 人（开局）的工期**：采集 1.0 天 / 加工 2.0 天 / 大型 4.0 天。
对比现状（所有东西固定 2 天、且**全部并行**）：便宜的快了、大件慢了、**多建要排队**。

## 四、队列

**建造与升级共用一条先进先出队列。**

```
每天结算：
    rate = 当日产能
    从队首依次投入：
        工程.remaining -= rate
        remaining <= 0 → 完工，溢出部分继续投给下一个
        产能耗尽 → 停止
```

## 五、工资

```
建筑工坊工人            100%  （固定工位、熟练度高）
失业人口 · 在工地上      80%  （临时工、非熟练）
失业人口 · 没工程可做      0%  （取消保障金）
```

⚠️ **这一条等于取消现有的失业保障金**（`economy.welfareRate` 作废）。
后果需要一并处理：

- `population` / `satisfaction` 里对"失业"的处理要重看 —— 收入为 0 会拉低工资满意度
- 无工程时全村失业人口收入归零，可能引发饥饿与迁出
- `README.md` 与 `docs/content.md` 里"失业保障：领取保障金（可温饱）"的描述要删
- 政府支出结构变化：保障金科目消失，新增建造工资科目

## 六、材料：开工时扣，不是下单时扣

```
下单  → 只检查材料是否够，占住队列位，**不扣**
开工  → 扣材料（木材 / 石块 / 粘土 / 砖）
        材料不足 → 停在队首等待，不跳过，写日志
```

好处：排队 20 天不会把材料压死，仍可周转。

## 十、分两步实现

**第一步**：产能（仅失业人口部分）+ 队列 + 开工扣材料 + 升级排队 + 建造工资三段结构。
建筑工坊暂时按"普通失业人口"计（即不享受 2.5 × 熟练度加成）。

→ 这一步就能让"人多盖得快、多建要排队"跑起来，且平衡数字容易验证。

**第二步**：接上建筑工坊的 `2.5 × (0.6 + 0.4 × 熟练度/100)`，并把熟练度成长接进建造力。

每步都单独对拍验证，出问题好定位。

## 十一、实现时踩到的两个硬约束

这两条不是设计选择，是这套模型**必然**导出的结构性事实，改 AI / 调平衡时必须知道：

### 1. 建造力归零 = 永久死锁，建筑工坊必须是第一座

产能 = 失业人口 + 建筑工坊工人。一个**全员就业且没有工坊**的村子产能恰好为 0，
于是既建不出工坊、也建不出任何东西 —— 死锁。

- 开局那批失业人口（v0.3 是 12 人）是唯一的起手资本，**必须优先拿去建建筑工坊**，
  而不是被食品链一次吃光（食物链满员正好要 14 人 > 12 人）。
- 基线 AI 因此把建筑工坊排在所有建筑之前（`src/ai/heuristic.ts` 第 0 步）。

### 2. 不能靠「压低开岗数」来给工地留人

迁入闸门是 `admit = min(arrivals, allowance, 住房容量−人口, **岗位数−人口**)`，
而「岗位数」= `Σ shop.targetWorkers`（`population.ts`）。一旦为了留建造队而压低
`targetWorkers`，岗位数就低于人口 → **一个移民也进不来** → 村子上限被锁死。

所以建造力**只能**靠建筑工坊（固定工位）提供，不能靠"少开几个岗"。基线 AI 全程满员开岗。

### 3. 施工是串行队列，下单必须限流（AI 侧）

旧模型下施工并行、固定 2 天，AI 每天下一个单也无所谓。串行队列下同样的行为会让
队列无限增长（队尾永远轮不到），所以基线 AI 加了 `MAX_CONSTRUCTION_QUEUE = 4`。

### 4. v0.2 没有建筑工坊

v0.2 内容包不含 `construction_works`，也就没有建造力增量来源，它的人口增长在此模型下
会明显受限（12 → 14 量级）。要修就给 v0.2 补一座工坊，或接受它只是教学包。
