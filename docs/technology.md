# 科技树设计（研究与解锁）

> 状态：**设计，尚未实现**。
> 本文是实装依据；实装后需同步改写 `docs/spec.md`（新增「研究」章节）与 `docs/content.md`（内容包 / 商品表的解锁列）。
>
> 一句话：**商品与建筑要一项项研究出来；最初级的食物链免费；研究花金币 + 原材料 + 时间。**

---

## 一、设计目标

1. **开局只有最基础的食物链**：穷人能吃饱（粗面包 + 蔬菜），有木材盖房子，有茅屋住。其余全靠研究。
2. **研究是"慢慢"的**：一次只推进一项，且需要若干天。研究进度**不**消耗建造力（见 §2.6），
   所以"慢慢"来自**排他性 + 天数**，而不是抢工人。
3. **花金币 + 原材料**：金币是财政压力，原材料是**产业链压力**——所有研究材料都必须来自**已解锁**的
   产业链（见 §1.1），于是"先能生产、才谈得上研究"。这是科技树真正的骨架。
4. **不打断现有经济**：不新增阶层、不改需求表、不改施工模型。科技只做一件新事——决定"能建什么"。

### 1.1 唯一硬规则：科技只花"已解锁"的原料

> **每一项科技消耗的每一种原材料，都必须由它自己或其前置（含传递前置）解锁的建筑产出，
> 或是开局免费的产出（木材）。**

这条规则让依赖图**自动闭合**：玩家不可能遇到"要研究 X 却要先有 X 的产物"的死锁。
本文所有花费都按这条规则核对过（§四给了依赖图，可逐条验证）。

## 二、机制

### 2.1 状态

```ts
interface ResearchProject {
  id: TechID            // 科技 id
  totalDays: number     // 总天数（进度条用）
  daysLeft: number      // 还剩几天
}

// GameState 新增：
research: {
  done: TechID[]              // 已完成
  queue: ResearchProject[]    // 先进先出；只有队首在推进
}
```

### 2.2 动作

| 动作 | 说明 |
|---|---|
| `research { techId }` | 入队。**下单即扣**金币 + 材料；前置未满足 / 资源不足 / 已完成 → `ok:false` 带原因 |
| `cancel_research { techId }` | 从队列移除（**不退款**）。用于腾出排他位 |

不提供"加速"：慢是设计要求。

### 2.3 每日结算

```
夜晚 settleResearch(state)：
    if queue 非空:
        head.daysLeft -= 1

黎明 activateResearch(state, day)：        # 与施工一致：昨晚跑完、今晨生效
    while queue 非空 and queue[0].daysLeft <= 0:
        done.push(queue[0].id) ; queue.shift()
        记日志「研究完成：<名称>」
```

与施工的关键区别：

| | 施工（`docs/construction.md`） | 研究 |
|---|---|---|
| 并发 | 一条队列，但**共用建造力产能** | 一条队列，**独占**，无产能概念 |
| 消耗 | 材料（开工时）+ 建造力 | 金币 + 材料（下单时）+ 时间 |
| 谁能做 | 失业人口 / 建筑工坊工人 | 不占人口 |

### 2.4 解锁判定

```
buildingAvailable(defId) =
    not 任何科技 unlocks 该建筑      # 开局免费的那批
 or 该建筑所属科技 ∈ research.done
```

- 每座建筑**至多被一项科技解锁**（数据校验会强制，见 §6.1）。
- **产品不单独设锁**：商品的可用性由"产出它的建筑是否解锁"决定（`解锁产品`列只是给玩家看的推导结果，
  不写进数据，避免两处真相）。
- 阶层需求表**不改**：某个商品没解锁，该需求就落在缺货替代链上（`fallbacks`），
  代价是满意度下降——这正是"该研究却不研究"的压力。

### 2.5 UI

- 建造栏（`build_bar.gd`）：**未解锁的建筑仍显示**，灰底 + 锁图标，tooltip 写「需要科技：营造（未研究）」。
  （不要隐藏——玩家需要知道有什么可追求。）
- 新增**科技面板**：按纪元分组；每项显示 名称 / 天数 / 花费 / 前置 / 解锁建筑与产品；
  可研究 / 研究中（剩余天数）/ 已完成 三态；顶栏加「科技」按钮。
- 顶栏信息行加「研究中：营造 2/3 天」。

### 2.6 为什么研究不消耗人力

已有的施工模型里，建造力 = 失业人口 + 建筑工坊工人（`docs/construction.md`）。
如果研究也抢这批人，两条队列会互相饿死，且很难向玩家解释"为什么工人去盖房就没法研究"。

所以研究**刻意不占人口**：它的成本是钱、材料和时间。好处是两条系统解耦、各自可调；
代价是少了"养学者"的层次。将来若要加，接口是现成的——

> **后续可扩展**：新增「学院」建筑，提供 `研究位`；没有学院时研究速度 ×0.5，
> 或干脆要求必须先有学院。这不动本文的科技树结构，只加一个产能乘数。

### 2.7 基线 AI

不给 AI 做花哨的启发式，用**固定的研究优先级表**（就是 §四依赖图的拓扑序）：

```
每天：若队列为空 → 取优先级最高且前置已满足、且买得起的科技，下单
```

优先级顺序 = 本文表格自上而下。理由：这个顺序本身就是"先补建材 → 再补建造力 → 再上中产 → 再上富庶"，
AI 照着走即可；且它保证 AI 不会把金币砸在富人奢侈品上而饿死穷人。

## 三、科技树总表

**共 27 项科技，5 个纪元，151 天，约 ¥7,990。**

- `天数` = 完成所需游戏日
- `花费` 里 `¥` 是金币，其余是仓库里的实物原料
- `前置` 是**知识前置**（成本材料来自哪些科技另见 §1.1 规则，两者可能不同）

### 纪元 0 · 起点（无科技，开局即可建）

| 建筑 | 产物 |
|---|---|
| 小麦农场 | 小麦 |
| 粗面粉磨坊 | 粗面粉 |
| 粗面包房 | 粗面包 |
| 蔬菜农场 | 蔬菜 |
| 伐木场 | 木材 |
| 茅屋（住房） | — |

> **为什么伐木场也免费**：木材出现在**每一座**建筑的 `buildCost` 里，锁住它等于锁住一切。
> v0.3 开局那 300 木材只够铺开初级产业链，不可能撑到"研究出伐木场"。
> 所以免费集 = **最初级食物链 + 木材 + 最基础住房**。这是对"最初级食物不需要科技"的最小必要扩大，
> 如果你希望更严格，可以把伐木场挪进纪元 1 的第一项（代价：开局必须先花 300 木材周转）。

## 五、开局与节奏（v0.3，12 人）

| 天 | 玩家应该在做 |
|---|---|
| 0 | 建 小麦农场 / 粗面粉磨坊 / 粗面包房 / 蔬菜农场；**第一座建筑工坊位留给研究** |
| 1–5 | 研究 石作 → 掘土 → 薪柴（3 × 2 天）；同时用开局 12 个失业人口的建造力铺粮食链 |
| 6–14 | 研究 营造（关键）→ 烧砖 → 制陶；建建筑工坊，开始有稳定建造力 |
| 15–30 | 研究 纤维作物 / 渔捞 / 木作住房；中产开始出现，补木屋与陶器 |
| 30–60 | 纪元 3 其余项；白面包 / 肉类 / 粗布衣 / 娱乐上线，中产满意度起来 |
| 60–110 | 纪元 4；奢侈品链成型，开始从富人身上收税 |
| 110+ | 纪元 5 |

**总量**：27 项 × 平均 5.6 天 ≈ **151 天**（不含等待资源的空窗）。
v0.3 现有验收跑 100 天，所以"全树通关"比当前验收长约 1.5 倍——这是刻意的，科技树就是长线目标。

```jsonc
      "era": 2,
      "days": 3,
      "cost": { "money": 150, "goods": { "clay": 30, "firewood": 25 } },
      "requires": ["digging", "firewood"],
      "unlocks": { "buildings": ["brick_kiln"], "housing": [] }
    }
  ]
}
```

**校验规则**（加进 `src/engine/content/validate.ts`，全部 `fail()` 而不是静默）：

1. `id` 唯一；`era` 必须存在于 `eras`；`days > 0`
2. `requires` 里的 id 必须存在；**依赖图无环**（拓扑排序检测）
3. `unlocks.buildings` / `unlocks.housing` 里的 id 必须存在，且**只能被一项科技解锁**（否则"解锁"语义模糊）
4. `cost.goods` 的 key 必须是本 pack 商品
5. **§1.1 规则自动校验**：对每项科技做传递闭包 `avail = {开局免费建筑} ∪ ⋃(前置科技的解锁)`，
   然后要求 `cost.goods` 的每个 key 都能由 `avail` 里的建筑产出。
   这条能直接挡住"要研究 X 却要先有 X 的产物"的死锁，**建议一定要加**。
6. 覆盖率报告（不 fail，只打印）：有没有商品永远产不出来？有没有建筑没被任何科技解锁也不在免费集？

### 6.2 `content/packs.json`

```jsonc
"start": {
  "population": 16,
  "techs": ["stonework", "digging", "construction"],   // 开局已研究完的科技
  ...
}
```

- v0.3：`"techs": []`（只有纪元 0 那 6 座）
- v1.0：`"techs": ["stonework", "digging", "construction"]`
  —— 它开局自带采石场 / 粘土坑 / 建筑工坊的**实例**，如果不把对应科技标为已完成，
  玩家会看到"我有一座采石场，但建造栏里的采石场是锁的"，很怪。

### 6.4 与其他系统的交界

- **施工**：`tryBuild` / `tryBuildHousing` 增加"该建筑是否已解锁"的检查（放在最前面，理由最明确）。
  `tryExpand`（扩产）**不需要**科技——已经建成的建筑升级不涉及新知识。
- **写死的建筑 id**：现在 `heuristic.ts` 与若干 UI 里**写死**了建筑 id（如 `'construction_works'`、`'lumberjack'`）。
  加科技后这些写死点要保证只引用"开局免费或已解锁"的 id；更稳的做法是把免费集也做成数据。
- **施工队的死锁**（见 `docs/construction.md` §十一.1）：科技树让"建筑工坊"变成必须研究的项，
  等于把原来的"第 0 步建工坊"变成"第 1 步研究工坊"。**必须保证营造的前置足够浅**（当前只有石作，5 天内可达），
  否则 12 人开局的建造力会在铺完粮食链后归零，而玩家连研究都还没做完——那才是真的死锁。

## 七、数值初值与平衡风险

**这些数字是设计初值，不是调好的值。** 实装后必须用 `npm run sim` 跑 100/200 天校准。

### 7.1 已经能看出来的风险：财政养不起研究

当前 v0.3 基线（100 天，AI，无科技）跑出来是：

```
人口 12 → 23    满意度 61.5    政府余额 2000 → -1413
```

**政府本身在亏钱**（私房租金流向只存不花的房主，这部分钱退出流通）。
而全树研究要花约 **¥7,990**，平均 **¥53/天**——比现在每天约 ¥34 的净流出还多。
照现在的曲线，科技树会**卡在纪元 3 前后**，因为买不起。

三个可用的杠杆，建议实装时按顺序试：

1. **研究费更多压在材料上、少压在金币上**（§1.1 已经保证了材料一定拿得出来）——
   材料是实物，不占用政府的现金。当前初值已经是这个取向，可以再压。
2. **提高奢侈品抽税能力**：`luxuryPriceMarkup`（现 2.5）与 `luxuryElasticity`（现 0.4）。
   富人链之所以存在就是为了把钱从富人手里抽出来，这正是付研究费的钱袋子。
   注意这会同时改变现有平衡，要重新跑验收。
3. **降低总天数/总费用**：如果 151 天太长，按比例缩（例如全表 ×0.7 → 约 106 天）。

### 7.2 次要风险

- **中产自动出现而科技跟不上**：中产由存款 ≥ 40 自动触发，与科技无关。
  如果研究太慢，会出现"一大批中产住在茅屋里扣满意度"的难堪期。纪元 3 的天数（5 天）
  是当前设计下最容易需要下调的一项。
- **木材是全局瓶颈**：几乎每项研究的材料都含木材。伐木场是免费的，但 `maxWorkers` 允许扩到 100，
  要确认 AI 会扩产伐木场，否则研究会卡在木材上而不是金币上。
- **`制陶` 与 `制瓷` 都用粘土**，`烧砖` 也用粘土：三者在纪元 2/4 争夺同一原料，
  粘土坑可能需要比现在更早扩产。

## 八、后续（本次不做）

- **学院 / 研究位**：见 §2.6 的扩展钩子——加「学院」建筑提供研究产能，
  研究速度与学者人数/熟练度挂钩，让"研究"也变成一条产业链。
- **时代门槛**：纪元 N 需要人口 / 满意度 / 前纪元完成数达标，避免玩家跳过纪元 1 直接冲富人链。
  当前设计只靠"前置 + 钱 + 材料"间接约束。
- **科技带来的非建筑效果**：例如"农学"给农场 +10% 产出、"医馆"降低饥饿死亡率。
  本文只做**解锁**，不做数值加成——加成会让 `docs/spec.md` 的公式契约复杂不少。
- **多局持久化**：跨存档保留已研究科技（Roguelite 式的"文明记忆"）。
