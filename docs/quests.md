# 任务系统（引导系统）

> **一句话**：任务是一条**对当前村庄状态的只读判定** —— 判到了就当场完成、当场发钱，
> 不需要玩家"提交"；而且**一次只露出一层**，玩家看不到后面还有什么。
>
> 契约（判定时机、奖励规则、goal 类型）在 `docs/spec.md` §16；内容在 `content/quests.json`；
> 两份实现：`src/engine/systems/quests.ts` 与 `godot/scripts/sim/sim_core.gd`（同口径同数字）。
> 界面两个：右侧**追踪条**（当前任务）与左侧圆钮打开的**任务面板**（全部已知任务 + 智囊口吻的描述）。

## 一、它解决什么问题

v0.3 开局是「12 个人、6 座茅屋、一座城镇中心、2000 金」，玩家第一次进游戏面对的是
36 种建筑、29 项科技、33 种商品 —— **没有引导就是纯挨打**。任务系统承担三件事：

1. **告诉玩家下一步做什么**（而不是一次把整棵树摊开）
2. **把因果讲清楚**：为什么先建小麦农场 → 磨坊 → 面包房（食物链）；为什么满意度是人口闸门
3. **给节奏**：每个任务 500 金 + 每章全绿再 1000 金，前期就是一笔能救命的工资池

## 二、口径（用户 2026-10 拍板）

| 问题 | 定下来的口径 |
|---|---|
| 要不要玩家"提交"？ | **不要**。黎明由仿真判定，为真即完成、立即发钱（"全自动"） |
| 判定什么时候做？ | **黎明**（`runDawn` 末尾 / GDScript `_run_dawn()` 末尾）。游戏里"生效"本来就都发生在黎明（建筑落成、科技生效），所以判定点天然与玩法同步，也天然可对拍 |
| 先干了、任务后出现？ | **照样算完成**。判定只看"眼前这个村子有没有"，与玩家何时接到任务无关；同一次黎明里还会**连锁结算**（刚建好的研究所把一条早就达成、只差它当前置的任务一起结算） |
| 奖励 | 每条任务 **500 金**（进国库 `government.money`）+ 一条公告；**每章**主线全绿再 **+1000 金**。支线不挡章节奖励 |
| 显示 | **渐进显示**：`requires` 没全完成的任务**根本不下发**（`quest_view()` 不返回它）—— 玩家不知道后面还有什么 |
| 完成态 | **完成即从追踪条上收走**（任务在黎明 6:00 结算，用户 2026-10 明确要求"每天 6:00 拿掉"）；达成但还没到黎明的标一句「已达成 · 次日 06:00 结算」 |
| 会不会回退？ | 不会。完成过就是完成过（人口掉回去也不算未完成），钱不重复发 |
| 进不进仿真？ | **进**。判定与发钱都在引擎里（TS + GDScript 两份），golden 一起重新生成 |

### 为什么是这些任务（每条的存在理由）

任务编号与 `content/quests.json` 的 `id` 一一对应（`qNN_xxx`）。

| # | 为什么要有 |
|---|---|
| 1 粗面包链 | 一个任务教完四件事：①放下第一座建筑（小麦农场是**田地**，顺带教地形/占地）②上下游加工（麦→粉→包）③建造队列、进度、工人数（6+2+2 人）④第一笔产能账：10 个工人养 24 人，正好等于开局 6 座茅屋的容量 |
| 2 蔬菜农场 | 教**第二种食物**与**易腐**（蔬菜不耐放，每天烂 10%）：只吃面包满意度顶不上去，囤 100 筐是假象 |
| 3.1 住得下 | 教**人口上限 = 住房容量**这条硬闸（移民 = `min(想来, 容量−人口, 人口上限−人口)`）：不盖房，满意度再高也不来人 |
| 3.2 按人口配产能 | 逼玩家**看产量而不是看库存**：开局 200 个面包会让人以为吃的问题解决了；要过 30 就必须上第二条链或学会「升级」（产量 ∝ 等级） |
| 3.3 让人愿意来 | 教移民门槛 55 / 迁出门槛 40，以及满意度是加权分（食物 0.45 最重）。玩家第一次必须去看顶栏那个数字 |
| 4 研究所 | 打开整棵科技树：研究力**只在研究所里产**（其他来源是 0）。同时教"产能建筑要派人" |
| 5.1–5.3 石作 / 掘土 / 薪柴 | 教"科技 → 解锁建筑 → 材料自给"这条主线，以及**地形要求**（采石场要石头地块、粘土坑要粘土、伐木场要森林）。木柴是砖窑/陶器坊/熏鱼坊的**燃料**，开局只有 40，不建就会在第一次烧砖时卡住 |
| 5.4 烧砖 | 砖是茅屋/木屋/砖房共同的料，也是初始库存里最快见底的；这一步把"住房扩张"从吃库存变成可持续 —— 1000 人终局的第一块基石 |
| 6 五十人的村子 | 第一个大台阶：检验 1–5 是否真的形成了"食物 + 材料 + 砖"的正循环 |
| 7 建筑工坊 | 教**建造力可以被建筑放大**（失业人口 1/人·天 + 建筑工坊在岗 2.5/人·天），也让玩家第一次感到张力：人都派去农场 → 没人盖房 |
| 8 石制工具（支线） | 教**工具/耗材**：有工具的工坊产出更高（与科技加成叠加）。支线，不挡主线 |
| 9 一百人的村子 | 到 100 人会开始暴露"只有面包+蔬菜"的天花板：满意度上不去、移民停滞 |
| 10.1–10.5 加工与舒适 | 中产/富人的需求清单就是这些（白面包、肉、衣服、陶器、娱乐）——不补上，人口变大后满意度会掉下来。同时把"易腐品要有加工兜底"（熏鱼/肉干）、"耐储奢侈品可以囤"（陶器）对照着教 |
| 11 中产 | 教**阶层由存款决定**（≥40 自动升中产），以及"**住房质量要跟着阶层**"：中产住茅屋会被扣满意度 —— 「只堆茅屋冲人口」的第一个天花板 |
| 5.5 初步修缮城镇中心 | 第一次"**花材料把旧东西支起来**"（不是新建）：它把开局的废墟变成第三张素材，也把第 3 章那四条材料线**收成一个看得见的成果**。用料只要木 20 + 石 10 —— 这时候玩家刚跑熟石作与薪柴 |
| 10.6 修复城镇中心 | 教**"花材料换脸面"**：修缮类任务的第二步。用料来自三条已经跑熟的产线（木/石/砖），做完之后城镇中心换成最后那张素材 —— 玩家第一次"看着自己修好的东西" |
| 12 二百五十人的村子 | 该从"铺新建筑"切到"升级扩产"了（一座 6 级面包房 = 144 个/天） |
| 13 富人 / 14 家政 | 教最高一档（存款 120、住房等级 3），以及富人的需求里**家政服务**也是需求、不是摆设 |
| 15 自己的房子（支线） | 教**私有化**：居民存款够、满意度 80 以上会自己买下国有住房，房款进国库、居民满意度 +12。绝大多数玩家会漏掉这条 |
| 16 五百人的村子 / 17 产能体检 | 1000 人的预演：先让食物产能撑到目标的一半，别在最后一头撞墙 |
| 18 千人之村 | 终局北极星。它同时压住五件事：住房容量、食物、材料链、就业、满意度 |

> ⚠️ 现在的住房容量是 茅屋 4 / 木屋 3 / 砖房 2（越"高级"越少），所以 1000 人 = **250 座房**。
> 用户 2026-10 明确"后期住房先不加"，所以终局确实是"点 250 次"——将来要缓解就加一档高容量
> 住房（`villa` 素材已在库里）或批量建造。

## 四、判定语言（`content/quests.json` 的 goal 类型）

每条任务 = `goals` 全为真 = 完成；每章 = 本章**非支线**任务全绿 = 章节奖励。

| type | 判什么 | 进度怎么算 |
|---|---|---|
| `building` | 已建成 N 座某建筑（在途工地**不算**） | `s["shops"]` 里同 `defId` 的条数 |
| `housing` | 拥有 N 栋某住房（国有 + 私有） | `s["housing"][id]` |
| `housing_capacity` | 住房总容量不低于 N | 与移民闸门同一个函数（`housingCapacity` / `_housing_capacity`） |
| `population` | 人口不低于 N | `residents.size()` |
| `class` | 某阶层人数不低于 N | 按 `classId` 数 |
| `tech` | 已完成某科技 | `research.done` 是否含它 |
| `tech_count` | 已完成科技数不低于 N | `research.done.size()` |
| `good` | 仓库里某商品不低于 N | `s["goods"][id]` |
| `produced` | **单日产量**曾达到 N（看产能，不看库存） | `history` 各天台账 + 今天的 `ledgerToday` 取峰值 |
| `avg_satisfaction` | 平均满意度不低于 N | 全体居民满意度的算术平均 |
| `private_housing` | 私有住房不低于 N 户 | `privateHousing` 求和 |
| `building_repaired` | 一座**塌了的**建筑修到了某段位 | `s["townCenter"]["stage"]`（id 可写 `townhall` 或 `town_center`）。缺省 `stage` = `restored`（已修好）；`stage:"patched"` = **至少**初步修缮过（已修好的也算）|

> `building` 还接受一个别名写法 `{type:"building", id:"town_center", repaired:true}` ——
> 口径与 `building_repaired` 完全一样（也认 `stage`），收着只是为了内容里换写法时不用改引擎。
> 两个引擎都有这条分支（`quests.ts::repairedOf` / `sim_core.gd::_quest_repaired`）。
>
> 城镇中心是三段（`ruined` → `patched` → `restored`，见 `docs/town.md` §二十六）：
> **第 3 章 `q05e_townhall_patch` 写 `stage:"patched"`，第 4 章 `q10f_townhall_repair` 不写（= 修好）**。
> 两种进度文案由引擎给：`城镇中心 已初步修复 0/1` / `城镇中心 已修复 0/1`
> （`repairStageWord` / `_repair_stage_word`，两侧逐字一致）。

**显示文案由引擎拼**（`QuestGoalProgress.text` / `quest_progress(qid)["goals"][i]["text"]`）：
UI 一个字都不自己拼 —— 否则 TS 与 GDScript 会显示出两种样子。数字一律向下取整。

## 五、界面：右侧的任务追踪条

- 位置：**顶栏下面的右侧**（用户要求，WoW 风格），固定宽 252，高度跟着内容走
- 标题行：图标（`quest_panel.png`）+ 「任务」
- 内容：每条 = 标题 + 一句「怎么做」+ 逐条目标（达标变绿）
- **只显示还没完成的**（用户 2026-10："面板每天 6:00 要把已经完成的任务从右侧面板中拿掉"）：
  任务正是在黎明 6:00 结算的，所以**刚做完的那条当场就从条上收走**（`quest_view()` 只返回未完成的，
  不再有"完成当天还赖一天"的旧口径）。完成了什么由**公告**和**任务面板**负责。
- 不吃鼠标（`MOUSE_FILTER_IGNORE`）：地图点击照常穿过去
- 最多画 5 条，多了用一行「…还有 N 条（做完会自己顶上来）」交代
- 刷新：`SimRunner.hour_ticked` 时重算一次（内容签名没变就不重建节点，避免闪）
- 实现：`godot/scripts/ui/quest_tracker.gd`（`main.gd` 里挂在 `UI/Root/QuestTracker`）

截图：`shots/quest-running.png`（开局两条并行）、`shots/quest-done.png`（刚完成 + 新任务被顶出来）。
截图模式：`screenshot.gd` 的 `quest` / `questdone`。

## 六、界面：任务面板（左侧圆钮第 5 个）

追踪条只讲"**现在**该做什么"（完成的不留）；面板讲"**这一路都做了什么**"。用户原话：
"任务面板放在左侧圆形菜单按钮…此面板记录之前完成的所有任务，左侧是可以展开收起的任务树（分章节），
选中任务后右侧显示任务描述…任务要求，完成情况。第几天完成。进入的显示当前未完成的第一个任务。"

- **入口**：左侧圆钮列第 5 个（图标 `quest_panel.png`，快捷键 **F5**）。
  浮动对话框（与「城镇中心」「AI 辅助」同一套：标题栏 + 拖动把手 + 关闭）。
- **左：任务树**，按**章**分组。章节行 = `▼/▶ 第 N 章 标题 done/total`，全绿领过奖励的补一个 `★`；
  点章节行展开/收起。任务行 = `标题 + 状态`（已完成 / 待结算 / 进行中），完成变绿、选中高亮。
- **右：详情**（用户点名的四件事，顺序照他说的）：
  1. **描述** —— 内容里的 `brief`，用**老臣（塞巴斯蒂安）**的口吻讲"为什么要做这一条"
  2. **要求** —— 引擎拼好的 `goal.text`（达标画 `◆` 变绿、未达标画 `◇`），下面跟一句 `批示：hint`
  3. **完成情况** —— 已完成写「已完成，第 N 天结算」；已达成未结算写"等黎明"；否则写「还差 k 项：…」
  4. **第几天完成** —— 写在标题下面那行（`第 1 章 先吃饱 · 要求 3/3 项 · 第 9 天完成`）
- **打开时默认选中第一个未完成的任务**（全做完则选最后一条）。
- 默认**只展开"选中那条所在的章"**：二十多条一起铺开反而找不到该做的那条；
  收起状态下章节行本身就交代了完成情况（`1/2`、`★`）。
- **渐进显示在面板上同样要守**：数据源是 `quest_journal()`，锁着的任务连"总数"都不参与计算
  （否则 `0/6` 就把后面有几条泄露了）。

截图：`shots/questpanel.png`（进行中）、`shots/questpaneldone.png`（已完成，带第几天完成）。
截图模式：`screenshot.gd` 的 `questpanel` / `questpaneldone`。

### `quest_journal()` 与 `quest_view()` 的分工

| | `quest_view()` | `quest_journal()` |
|---|---|---|
| 给谁用 | 追踪条 | 任务面板 |
| 范围 | 未完成的（已解锁）+ **今天**刚完成的 | 未完成的（已解锁）+ **全部**已完成的 |
| 为什么 | 屏幕上只能挂几条，玩家要的是"现在做什么" | 玩家要能回头翻"我做过什么、第几天做的" |
| 锁着的 | 不返回 | 不返回（同一条契约） |

两份实现：`src/engine/systems/quests.ts::questJournal` 与
`godot/scripts/sim/sim_core.gd::quest_journal`（同口径；门槛两边都锁）。

## 七、剧情对话（任务触发 / 章节收尾，用户 2026-10）

两条都做成 **galgame 形式**：右侧立绘滑进来、下中一个米黄文字框、说一句点一下翻页
（`▼` 闪动提示可以继续），**对话期间时间暂停**。

| 何时 | 说什么 | 数据 |
|---|---|---|
| **任务一出现在追踪条上** | 发布人（`giver`）把这条任务的 `brief` **逐句**说一遍 | `quests[].giver` / `giverPortrait` / `brief` |
| **一章主线全绿（领章节奖励那一刻）** | 内容里的 `chapters[].outro`: `{ speaker, portrait, lines, choices? }` | `chapters[].outro` |

### 引擎给、界面画

`SimCore.quest_talks_pending()`（TS 侧 `quests.ts::questTalks`）返回**还没播过的**对话：

```jsonc
{ "key": "q:q01_bread_chain", "kind": "quest", "id": "q01_bread_chain", "chapter": 1,
  "speaker": "sebastian", "portrait": "sebastian_neutral",
  "lines": ["殿下，仓里那点存粮是死数：……", "……", "……"] }
```

- **顺序 = 内容顺序，按章交错**：第 1 章的任务 → 第 1 章的收尾 → 第 2 章的任务 …
  这样第一章一结束（第二章任务同时解锁）时，瑟拉菲娜的登场**不会**插在露娜的
  「蔬菜农场」后面。
- 播完界面调 `quest_talk_mark_shown(key)`，记进 `s["quests"]["shown"]`。
- 判定方式是**状态比对**而不是事件队列：队列会丢（读档 / 退出重进就丢），比对不会 ——
  所以既不重播也不漏播。`shown` 与 `prophet` / `townCenter` 同一类：**只记事、不演化**，
  黄金摘要按字段取，碰不到它。

### 台词怎么来的

`brief` 按**句末标点**（`。！？…`）切页，`：，、` 不切（切了一句话就断成两截，念起来不像人话）。
所以 `brief` 必须是**能当台词念的一段话**，不是提纲 —— 这条要求已经写进内容校验器（非空）
和 `docs/quests.md` §十的第 1 步。

### 选项（`choices`）

```jsonc
"choices": [{ "id": "accept",  "text": "……说下去。", "action": "free_prophecy" },
            { "id": "decline", "text": "不必了。",     "action": "close" }]
```

`action` 只有两个合法值：`free_prophecy`（送一次预言）/ `close`（什么都不做）。
带选项的最后一页**点空白不算选**，得真按一个按钮；「跳过」/ Esc 等于放弃。
第一章收尾选 `accept` → 打开预言面板并**当场问一次**，这次**不吃 5 天冷却**
（`ai_panel.open_free_prophecy()`：`ask(free = true)`，答完不记 `mark_prophet_asked`）——
她自己在剧情里送上来的，不该让玩家一进游戏就被罚等 5 天。

### 人物 id 的三种拼法（`scripts/ui/cast.gd`）

内容里是 `renard` / `vila` / `seraphina`，立绘文件叫 `reynard.png` / `vera.png` / `serafina.png`。
所以「id → 中文名 / 立绘」只有一份实现：`Cast.speaker_name()` / `Cast.portrait()` /
`Cast.portrait_head()`。`<人>_<表情>` 先找表情差分图（`assets/portraits/<人>_<表情>.png`），
没有就落回这个人的默认立绘。以后画了表情差分，**放文件就行**，代码不用动。

### 预言家按钮：第一章收尾之前不出现

瑟拉菲娜是第一幕之外**只在第一章结尾登场**的人，所以在她登场之前：

- 左侧圆钮列的「预言」（`NAV_PROPHECY`）**藏着**（`hud.refresh_nav_buttons()`）
- 顶栏那个水晶球按钮也藏（`hud.refresh_ai_btn()`），`_open_ai()` 里还有第二道闸
- 判据只有一处：`SimCore.prophet_unlocked()`（= `quests.chapters["1"]` 有没有记录）

ESC 菜单里的「AI 辅助设置」不受影响（那是**配置**，不是预言家本人在场）。

## 十、加一条任务怎么做

1. `content/quests.json` 里加一条（`id` / `chapter` / **`giver`** / **`giverPortrait`** /
   `title` / `hint` / **`brief`** / `reward` / `requires` / `goals`）
   - `brief` **必填**（校验器会拦空的）：一句话讲清"为什么值得做"，口吻是**发布人**的；
     它还会被**逐句念**出来（任务触发对话），所以必须是能当台词念的话
   - `giver` / `giverPortrait` 也**必填**：少了就是"任务静静地出现"，玩家注意不到
   - 描的字要用像素字体有的字（`⚠ ≤ ≥ √ ✓` 都没有）—— 门槛 `glyph` 会扫 `content/quests.json`
2. `npm run sync:content`（副本必须逐字节一致）
3. `npm run check:content`（会校验引用存在、`requires` 无环、支线不被人依赖、`brief` 非空、
   `giver` 非空）
4. 想锁住行为就补一条断言到 `scripts/check-quests.ts` 与 `godot/tools/quest_test.gd`
5. 若任务会改到"某一章会不会被提前领掉"，跑 `npm run golden` 重生成 + `godot verify.sh`
