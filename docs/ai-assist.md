# AI 辅助（告诉玩家下一步做什么）

> 界面口径在 [docs/town.md](town.md) §十八；这里是**功能契约**：算哪些数、怎么拼提示词、
> 配置存哪儿、门槛锁什么。

顶栏那颗**水晶球**（**暂停按钮左侧**）、左侧圆钮第 6 个「预言」都进**全屏预言页**，
ESC 菜单里的「AI 辅助设置…」进**设置页**。
三处（外加面板标题）用的是**同一张图标**：`godot/assets/ui/panel/ai_assist.png`
（水晶球，workbuddy 那套面板图标里的，见 `godot/assets/CREDITS.md`）。
它做两件事：

1. **程序计算**：把当前局势算成"下一步做什么"（**不联网**，永远有）
2. **问大模型**：把「游戏规则 + 局势数据 + 程序算出的候选」发给 LLM，让它排序 + 讲因果

第 1 条不是第 2 条的兜底，而是它的**前提** —— 见下面「为什么先算再问」。

```
顶栏 [AI 辅助] ──┐
ESC 菜单 ────────┴─→ ai_panel.gd ──┬─→ sim/advisor.gd   算（只读、纯函数、headless 可测）
                                    │        ↓ messages()
                                    └─→ ui/ai_client.gd  发（HTTPRequest，OpenAI 兼容）
                                             ↓ replied / failed
                                       再回到 ai_panel.gd 画
```

| 层 | 文件 | 干什么 | 为什么放这一层 |
|---|---|---|---|
| 配置 | `godot/scripts/core/ai_config.gd` | 读写 `user://ai.cfg` | 基础设施；sim 层不许碰文件 |
| 计算 + 提示词 | `godot/scripts/sim/advisor.gd` | 只读聚合、规则引擎、拼 messages | 与引擎同层，能直接调 `_cost_of()` 等口径函数；纯 RefCounted，headless 可跑 |
| 接入 | `godot/scripts/ui/ai_client.gd` | HTTP + 响应解析 + 回答清理 | 要挂 `HTTPRequest`（Node），只能在表现层 |
| 界面 | `godot/scripts/ui/ai_panel.gd` | 两页对话框、信号接线 | 纯粹画 |

**这条功能不改仿真行为**：`Advisor` 从头到尾只读 `sim.s`，也从不入队命令
（门槛 `ai_test` 里有一条"跑完全套之后 `sim.s` 逐字节不变"的断言）。
所以 `golden/` 不需要因为 AI 辅助重新生成。

⚠️ 只在 Godot 侧实现，**没有 TS 版**。理由：TS 引擎没有 UI（`src/api/server.ts` 是给
"会下棋的 AI"用的接口，`src/ai/heuristic.ts` 是那套自动玩法的基线策略 —— 与本功能
目的不同：那个**替玩家玩**，这个**告诉玩家怎么玩**）。将来 web 版若要同一份顾问，
`advisor.gd` 的口径可以机械地照抄成 `src/engine/systems/advisor.ts`：它引用的所有
数据（`db.*`、`goal.text`、`_cost_of`）两边都有。

## 一、为什么"先算再问"

让模型自己数库存、自己比轻重，它**会编**。所以流程是：

1. 程序把"事实"算清楚：库存多少、缺多少、还够几天、哪个原料在卡产能、满意度短板是哪一项
2. 这些事实连**具体数字**一起写进提示词
3. 提示词里明确要求：**只许引用给出的数字**，不要自己算

模型于是只剩"排序 + 讲因果"这一件事 —— 那是它擅长的，也是唯一需要它的地方。
（本地计算还有独立价值：没配 key、断网、模型抽风时，玩家照样有一份能照做的建议。）

⚠️ 2026-10 起这条又往前一步：光"看账"不够，模型还能**把村子拿到沙盘上试着跑几天**
（见 §五）—— 于是它的结论从"我觉得先补粮"变成"我试了 6 条路，先补粮那条 5 天后人口 +1"。
数字仍然全部来自引擎，只是从"当前状态"扩展到了"跑完之后的状态"。

## 二、程序计算的口径

两条硬规矩：

- **只读**：`Advisor` 从不写 `sim.s`、从不入队命令 ⇒ 不影响确定性、不影响黄金轨迹
- **不重抄公式**：够不够 / 缺多少 / 能产多少，一律调引擎**自己的**函数
  （`_cost_of()` / `_can_afford()` / `_shortage_reason()` / `_assigned_workers()` /
  `_shop_tool_boost()` / `_sector_output_boost()` / `construction_rate()` / `research_rate()`
  / `_is_researched()` / `_is_queued_tech()` / `housing_capacity()` / `job_capacity()`）。
  数字要错就两边一起错、一起修。**这一层里没有一个经济公式。**

| 算出来给玩家看的东西 | 从哪儿来 |
|---|---|
| 住房容量 / 空床 / 各房型座数 | `housing_capacity()`、`s.housing`、内容 `housing.json` 的 `capacity` |
| 岗位 / 在岗 / 失业 | `job_capacity()`、`s.residents[].employed` |
| 基础食物「日需」 | 各阶层 `needs[].perCapita` × 该阶层人数（**名义值**，实际消耗看台账） |
| 基础食物「本日产」 | Σ `shop.planned` × 配方产出 × 工具与科技加成（`planned` 是黎明算好的，已按原料打折） |
| 「还够几天」 | 库存 ÷（名义日需 − 本日产），基础食物（`tuning.basicFoods`）可以互相顶，所以合起来算 |
| 「这块料在卡产能」 | 黎明 `_plan_production()` 把该留的料记在 `s.reserved`；库存压到预留线以下 = 它在卡 |
| 满意度短板 | 逐人账目里当天记下的 `foodScore / comfortScore / priceScore` + 在岗与否，权重取 `economy.weights`（**读，不重算**） |
| 建得起吗 / 缺什么 | `_cost_of({"kind":"shop"|"housing",…})` + `_can_afford()`，逐项比库存 |
| 科技闸门 | `tech_for_building()` / `tech_for_housing()` + `_is_researched()` |
| 「还要几座」 | 拿现有同类建筑的**观察产量**（本日计划产量 ÷ 座数）当"一座能产多少"，不重算 baseRate 公式 |
| 升阶还差多少 | `promotionSavings` / `promotionSatThreshold`（内容）+ 逐人账目的 `wage - tax - rent - spent` |

`Resident.account` 里已经有 `foodScore / comfortScore / priceScore / wage / tax / rent / spent`
（消费结算时写进去的），所以满意度诊断不需要动仿真状态。

## 三、建议规则（`plan()`）

按紧急度排序，按 `id` 去重（同一个病只开一张方子），最多 6 条。

| 优先级 | 规则 | 什么时候触发 | 红线 |
|---|---|---|---|
| `P_URGENT` | `food_shortage` | 昨天有人挨饿，或基础食物不足 3 天 | 已经在饿死人 |
| `P_URGENT` | `sat_low` | 平均满意度 < 流失线（40） | 已经在搬走 |
| `P_HIGH` | `housing_full` | 空床 < 本回合想来的人数 | 移民进不来 |
| `P_HIGH` | `no_build_power` | 有工程但当日建造力 = 0 | 村子卡死 |
| `P_HIGH` | `quest_*` | 任务的未达成目标（一个任务只开一张方子，最多 3 个任务） | 引导主线 |
| `P_HIGH` | `sat_low` | 平均满意度 < 移民门槛（55） | 卡住成长 |
| `P_HIGH` | `research_stalled` | 队首科技但科研力 = 0 | 科技不动 |
| `P_NORMAL` | `unemployed` | 岗位 < 人口 | 满意度扣分 |
| `P_NORMAL` | `storage_full` | 仓储已满 | 产的白产 |
| `P_NORMAL` | `research_idle` | 有研究所但研究队列空 | 产能浪费 |

任务目标（`goal.type`）→ 具体方子：

| 类型 | 方子怎么给 |
|---|---|
| `building` | 指名「建造栏『某页』建 N 座 X（材料…）」；缺科技先说"先研究 Y"；缺料再说"某料由某建筑产" |
| `housing` | 指名房型与座数 |
| `housing_capacity` | 按"每个床位最省材料"选房型，算出**还差几个床位 = 建几座** |
| `population` | 移民的三个闸门逐个报（空床 / 满意度 / 昨天饥荒），指出卡住的那个 |
| `class` | 升阶门槛（储蓄 / 满意度 / 住房质量）+ 现在平均储蓄、每天净攒多少、还差几天 |
| `tech` | 研究所提示 + 前置科技 + 研究材料缺口 + 是否已在队列 |
| `tech_count` | 同上，另给一项"现在能研究的" |
| `good` | 还差多少 + 现在每天产多少 + 约几天攒够 + 建几座加速 |
| `produced` | 历史上最好的一天产了多少、目标多少、还差多少、建几座；卡在原料时点名是哪样 |
| `avg_satisfaction` | 走满意度诊断（和 `sat_low` 同一个 `id`，会去重合并） |
| `private_housing` | 私有房是居民自己买的：抬满意度，房子不用玩家建 |

⚠️ **`Advisor.KNOWN_GOAL_TYPES` 必须覆盖内容里出现的每一种 `goal.type`。**
内容加了新类型而这里没跟上 → 那条任务在建议里**静默消失**（玩家少一条引导，不报错）。
门槛 `ai_test` 拿内容里的全部类型跟这张表对拍，就是防这个
（同一套手法见 `src/ai/heuristic.ts::assertResearchOrderComplete`）。

两条消息（OpenAI 的 `messages` 形状）。

### 人设：**瑟拉菲娜**（用户 2026-10 给的完整设定）

| 项 | 设定 |
|---|---|
| 姓名 | **瑟拉菲娜**（Seraphina） |
| 年龄 / 身份 | 22 / 神秘预言家 |
| 性格 | **猫系、傲娇、神秘、慵懒** |
| 外貌 | 黑长直、**紫瞳**、眼角一颗**泪痣** |
| 服装 | **紫色露肩长裙**、面纱、首饰 |
| 体型 | 高挑、纤细 |
| 语气 | 「**哼，才不是特意为你预言呢。**」 |
| 表情 | 平静 / 傲娇 / 挑逗 / 沉思 / 神秘 / 满意 / 不悦 / 惊讶 |
| 立绘 | 8 张（好感度 6 档 + 2 特殊）—— 见下面的"还没做的" |
| 好感度 | 核心系统（6 档）—— 还没做 |

system 提示第一段就把她立起来：名字、22 岁、黑长直紫瞳泪痣、紫色露肩长裙配面纱，
性格**猫系傲娇**（慵懒、爱理不理、话里带刺，嘴上永远不承认自己在意），
但**算得比谁都准**：一旦开口，每个数、每座建筑名都落地。

**来问的人是谁**（2026-10 改过一次）：不是村民，是**这块封地的主人 —— 刚受了封的王子**
（见 [story.md](story.md)）。但她对他从来不客气：提示词里最后一句只说
「按上面的格式答问话的人」，**不给她"殿下"这个称呼** —— 她要么直说，要么根本不叫。
改这条**是为了跟故事设定对齐**，不是加戏：原来写的是"村里人偶尔来求你"，
和"被分封的王子"这条主线打架。

**傲娇是语气，不是内容** —— 这条写死在提示里：内容必须冷、硬、具体，
不许用"要有信心""来日可期"这类没有信息量的话搪塞。人设最容易滑向含糊其辞，
而殿下来问是要一个**准话**。

### ⚠️ "有人设" ≠ "像人设"：口吻那一段比规矩更管用

2026-10 上线的第一版提示词**人设全写了，但真模型答出来是报账**：

> 我看见了：为什么工地一动不动 —— "什么都不做"到第 57 天建造力是 10，住房容量是 48、
> 空房 0；我拨「先建造力」把两座建筑工坊填了人，建造力升到 13，可第 57 天住房容量还是
> 48、空房 0，一间茅屋都没立起来。

数字全对、一条没错，**但没有一点预言家的味道**。原因在提示词自己身上 ——
它当时同时在逼模型堆数字：`征兆：必须引用给出的数字` + `把建筑名、缺的料、还差几天说死`，
再加上【本地计算】整块都是账房体。模型照做了，于是写成账本。

**改法**（当前版本）：

1. **「口吻」那一段排在"规矩"前面**，标题直接写"这条最要紧，比数字重要"；
2. 给**正反两个例子**（few-shot 比一百个形容词管用）：
   正的 = "球里的工地空着，绳子被风吹得直响 —— 全村都在歇手"；
   反的 = "第 57 天建造力是 10，住房容量 48、空房 0…"；
3. 硬规矩：**一条征兆最多一个数字**，而且要用粗的（三座 / 五天 / 够吃两天）；
   **绝对不许连着报账**；"点哪里"只归 `应对` 那条管；
4. 规矩 1 补半句：数字只能来自给出的数据，**但"有出处"不等于"都要说出来"**；
5. 【本地计算】那段抬头加一句"这些是账目，说话时翻成村里的话，**不要照抄这些数字**"。

改完真跑一次（`aireal`）：`我看见了：球里的菜畦空着，连一棵菜都没有冒头，风都把土表吹干净了
—— 全村人的菜缸是空的。` 后面三条建议里只出现「两座 / 一个 / 三座 / 五天」这种粗数量。
**结论：人设不是靠"写一段性格"立起来的，是靠"禁止什么写法 + 给一个范例"。**

### 她"看见未来"的说法：**水晶球**，不是沙盘

用户 2026-10："不要说什么沙盘，可以说从我的水晶球里可以看见。"

- **代码内部**还叫沙盘（`Trial` / `_briefing()` 里的注释），但**模型看到的每一个字**
  都按水晶球写：工具名 `scry`，描述是"拨开水晶球里的雾，看某一卦的结果"，
  一卦 = 一条方案，球里显现 = 跑完的结果，"成不了" = 被引擎拒。
- system 提示第 9 条明写：**不许自称 AI / 助手 / 模型，也不许提系统、程序、模拟** ——
  你看的是水晶球，算的是命。
- **面板上一条沙盘数据都不画**（下一条），玩家只看见她在拨球（`ai_panel.ORB_LINES`
  轮换的那几句），和最后的进言。
- 门槛 `ai` 有一条断言扫**模型看到的全部文字**（系统提示 + 简报 + 工具声明），
  出现「沙盘 / 模拟引擎 / 引擎拒绝」就红 —— 这条是防回归的关键，别删。

⚠️ **人设是外壳，硬约束一条都不能松**：

| 硬约束 | 为什么 |
|---|---|
| 不要自己算数、不要推测没有的数据；要数字就引用给出的数字 | 模型自己数库存必编 —— 这是"先算再问"这一层的存在意义 |
| **只讨论列出的任务，绝对不要猜测或提及还没出现的任务** | 任务系统是**渐进显示**，剧透就废了引导 |
| 不要 Markdown（不要星号加粗 / 井号标题 / 短横线列表 / 表格 / 代码块） | 面板用像素字体画纯文本，`**` 会原样显示成星号 |
| 用中文，建筑名 / 商品名一律照抄给出的表 | 模型会自己造名字（"磨面厂"），玩家照着点找不到 |
| 本地计算是算好的候选项，你的工作是排序 + 讲因果；不同意就说出依据的数字 | 让模型在候选之间做取舍，而不是重新算一遍 |
| 每个数字都要有出处 | 说「石料还差 12」之前，先在数据包里找到它 |
| **口吻是外壳，里面的东西要硬** | 见上 |

人设只影响**怎么说**，不影响**说什么**：`Advisor.plan()` 算出来的候选、`situation_text()` 里的
每个数字，都还是账房那一套。

### user —— 四块

| 块 | 内容 | 大小（开局 / 66 人时） |
|---|---|---|
| 【游戏规则】 | 时段、命令次日生效、只花材料、生产的打折与缺料、各阶层需求、满意度权重与惩罚、移民公式与闸门、仓储超限、科研 / 建造力、私有房、任务奖励 | ~1.5 KB |
| 【局势数据】 | 概况、阶层、住房、岗位 / 建造力 / 科研力、仓储、食物（含逐项）、每座建筑（在岗 / 本日产 / 卡在原料）、建造队列、关键物资、科技、**当前任务**、**可建清单** | ~2 KB / ~9 KB |
| 【本地计算】 | `plan()` 的候选（带数字依据） | ~0.5 KB |
| 【殿下的问话】 | 面板上玩家自己写的那一行（默认「我下一步要做什么」，见 §五） | 一行 |

有问话时最后一句是「现在，用你的口吻回答上面那句问话（先在「我看见了：」那行答他，再给该做的事）」；
没有（脚本 / 门槛直接调 `messages()`）时退化成「现在，用你的口吻告诉我：接下来最该做的是哪三件事？」。
system 里对应多了第 8 条：**先答那句话，再给该做的事**；问的和局势对不上就照实说看见了什么。

两个刻意的设计：

- **规则里的数字全部从内容里取**（`db.economy` / `db.classes`），所以改经济参数时提示词自动跟着变。
  门槛里有一条"改一个参数，规则摘要跟着变"的断言。
- **「可建清单」只列当前科技下可建的**，且**排除地图上固定的那几座**（城镇中心）——
  列进去模型就会建议"再建一座城镇中心"，而建造栏根本不给建。

### 输出格式（用户 2026-10 亲自定的，就是这四样）

```
我明白了，你想要知道「（把玩家问的那句抄进来）」
我看见了，你应该（一句话给判断 —— 这就是结论，原先放最后，现在提到前面来）
（措施）一句话：派谁去做什么，会怎么样（球里看见的结果）
（措施）一句话：派谁去做什么，会怎么样
```

- **不要编号**，**不要「征兆 / 应对 / 预言」这些标签**，也**不要每行自己加小标签**。
- **措施一条一句**，最多 3 条，按轻重缓急；每条都要有 **「派谁 + 做什么 + 会怎样」**。
- ⚠️ **「派谁」= 世界里的人**（用户 2026-10：「让她用世界里的说法点一句，比如『让木匠把菜园的
  架子搭起来』，不提页签。当然是这样，这样有沉浸感」）：盖房有工匠、种地有农夫、
  磨面有磨坊工、读书有读书人、采石有石匠。**一个字都别提界面** ——
  玩家原话：「为啥瑟拉菲娜会操作游戏呢？这个破坏沉浸感」。她是预言家，不是管家。
- 建筑名仍照抄内容表（蔬菜农场就是蔬菜农场），工匠只是**执行的人**。
- 问「为什么」时，把答案并进「我看见了」那一句（**不另起一行**）。
- 结论**放在前面**（"我看见了，你应该…"），措施跟在后面 —— 这是把原来末尾的
  "预言/总结"提到最显眼的位置。

真端点跑出来的样子（`deepseek-flash`，2026-10）：

```
我明白了，你想要知道「我下一步要做什么」
我看见了，你应该先把菜畦开出来 —— 球里「菜加面」那一卦，五天之后蹲在门口等饭的人只剩一个…
先让工匠建起两座蔬菜农场，农夫架着种下种 —— 球里「三座菜园」和「菜加面」都是这个结果…
菜园落成当天就把人派足，让农夫进去干活 —— 空园子跟荒地没两样，早一天下种，菜缸早一天不见底
再让面包师给粗面包房多起一座炉子…另外让工匠把茅屋盖起来，外面等着进村的人才有地方落脚
呀，别以为我特意替你算了这么多卦
```

面板按这个着色（`ui/ai_panel.gd::_render_reply()`）：
「我明白了」暗色、「我看见了」深色（结论）、措施原样。
⚠️ 前缀表里还留着旧的 `征兆`/`应对`/`预言`/`为什么`/`怎么做`/`总结`：
模型偶尔不照新格式写，画出来也不该乱。**但提示词里不许出现这些词**（门槛会红）——
向模型提一句"不要征兆/应对"反而等于把禁词喂给它（踩过两次：`沙盘` 与这次的 `征兆`）。

## 五、多轮：让她**多拨几卦水晶球**

> 代码和这份文档里仍叫它"沙盘 / `Trial`"，因为那说的是机制；
> **玩家与模型看到的永远是水晶球**（见 §四·她"看见未来"的说法）。

用户 2026-10 定：

> "ai预测不应该只有一轮llm对话，应该把游戏模拟引擎作为一个tool给ai，让他可以在决策后，
> 跑一下看看后续几天会怎么样。正常可以让他给5日的决策，3-5个方案，然后跑一下看看结果，
> 返回结果。如果ok就回答，如果不ok，再来3-5个方案再跑。不能超过3轮（第三轮要告诉他这是最终轮）"

### 一次"问话"= 一场多轮会话

```
第 1 轮  给 3~5 个方案 ─→ 沙盘各跑 5 天 ─→ 把结果喂回去
第 2 轮  不满意就再给 3~5 个（换思路）─→ 再跑 ─→ 喂回去
第 3 轮  **明说"这是最后一轮"** ─→ 再跑最后 3~5 个
收尾     关掉工具 ─→ 让它按预言家的口吻给结论（数字只能来自沙盘或局势包）
```

也就是**最多 4 次 HTTP 请求**（3 轮试方案 + 1 次收尾）；某轮直接给结论就提前结束。
代码：状态机在 `godot/scripts/sim/prophet_agent.gd`（纯的、可 headless 测），
面板 `ai_panel.gd` 只负责"把 `next_request()` 发出去、把回来的交给 `accept()`"。

| 常量 | 值 | 含义 |
|---|---|---|
| `ProphetAgent.MAX_ROUNDS` | 3 | 最多几轮试方案（用户："不能超过3轮"） |
| `ProphetAgent.MAX_PLANS` | 5 | 一轮最多跑几个方案（用户："3-5个方案"） |
| `ProphetAgent.TRIAL_DAYS` | 5 | 沙盘默认往前跑几天（用户："5日的决策"） |
| `Trial.MAX_DAYS` / `MAX_MANDATES` | 5 / 12 | 单个方案的天数上限 / 命令条数上限 |

### 沙盘（`Trial`）：引擎当工具的那一件工具

> 面板上**一条都不画**（用户 2026-10："沙盘（本地引擎跑的）全部去掉，破坏沉浸"）。
> 玩家只会看到她在拨球；这一节的产出只喂给模型。

`godot/scripts/sim/trial.gd`。**四条硬要求**：

1. **不碰真实状态**：只读 `source.s`（`duplicate(true)` 出副本），跑完当作没跑过。
   门槛 `ai_test` 拿"跑完沙盘之后 `sim.s` 逐字节不变"钉这一条。
2. **命令走引擎自己的命令**：方案被翻译成 `_apply_actions()` 认的动作，交给
   `tick_hour()` → 黎明 `_apply_actions()`。**绝不另写一套规则** —— 缺料、科技没解锁、
   村里还没有那座建筑，全由引擎自己拒，沙盘只**如实报告**（`rejected` 里写人话）。
3. **确定性**：同一份状态 + 同一个方案 = 同一个结果（rng 状态一起复制），跑两遍逐位相同。
4. **省着花**：天数 ≤ 5、命令 ≤ 12。实测克隆 0.1~0.4 ms、跑 5 天 6~15 ms，
   **一轮 5 个方案 ≈ 20~30 ms**，所以同步跑、不用线程、不用分帧。

**刻意收窄的命令集**（`Trial.KINDS`）：`build` / `build_housing` / `expand` / `research` /
`set_workers`。拆房、改税、改价这些会把村子搞乱的操作**不开放给模型试** —— 它可以建议，
但不能在沙盘里乱试。`id` 一律用**建筑 / 住房 / 科技的 id**（不用背 `wheat_farm#1` 这种实例 id）。

**喂回去的东西**（每个方案一条 `role:"tool"` 消息）：

```json
{"label":"先补粮","days":5,
 "end":{"day":14,"pop":67,"sat":74.2,"hungry":0,"money":500100,
        "housing":{"cap":70,"vacant":3},"jobs":110,"employed":108,
        "food":{"粗面包":{"stock":12,"perDay":40,"daysLeft":99}},
        "materials":{...},"shops":41,"construction":3,
        "questsDone":11,"problems":["住房满了：移民住不进来", ...]},
 "delta":{"pop":1,"sat":0.5,"money":-275,"hungry":0,
          "jobs":0,"shops":0,"construction":1,"food":{...},"materials":{...}},
 "newQuests":[], "rejected":[]}
```

- `delta` 是跟**"什么都不做"跑同样天数**比的（对照算一次、缓存）；不复用对照，delta 没有意义。
- `shops` / `construction` 的差是判断"**这一手到底落没落地**"的关键：5 天里很可能只排上队、
  没盖完 —— 模型要能看到这件事，否则会把"排队"当成"建成了"。
- `problems` = 在沙盘上再跑一遍规则引擎（`Advisor.plan()`）取前 3 条 + 食物/饥饿告警。
- `daysLeft = 99` 表示**产量够吃**（不是"99 天"）。别用 -1：模型会读成"负的天数"。

### 两条协议都认

| 协议 | 什么时候用 | 怎么认 |
|---|---|---|
| **原生 function calling** | 主流端点（DeepSeek / OpenAI / ollama / vLLM / llama.cpp） | 请求带 `tools` + `tool_choice: "auto"`；响应读 `choices[0].message.tool_calls[]`（`arguments` 是 **JSON 字符串**，顺手解析） |
| **文本兜底** | 不支持函数调用的端点 | 回复里带 `{"actions":[...]}` 的 JSON 块 → 当成方案跑掉。**只在正文很短时**认（否则会劫持"结论里贴的方案"） |

`arguments` 解析失败 / 工具名不认识 → 都**回一条 `role:"tool"` 说明原因**（而不是整条失败）：
模型下一轮能自己改。轮次用满之后它还想试 → 不再跑沙盘，直接转收尾（`tools` 关掉）。

### 真端点实测（2026-10，`deepseek-flash`）

上线前拿真 key 打过一次（`screenshot.gd` 的 `aireal` 模式，不灌假配置）—— **发现三个真问题**，
都是假模型测不出来的：

| 现象 | 原因 | 改了什么 |
|---|---|---|
| 「模型返回了空内容」，6 秒就失败 | `max_tokens` 只有 1200，而它是**推理模型**（响应里带 `reasoning_content`，一次思考 500 字）；长提示词 + 一轮 3~5 个方案的 JSON 直接把预算烧完 → `finish_reason=length`、`content` 空、`tool_calls` 残缺 | `AiConfig.DEFAULT_MAX_TOKENS` 800 → **4000**，用户配置里也给 1200 → 4000 |
| 方案里写 `{"id":"farm"}`、`{"id":"house"}` 这种**自己编的 id**，沙盘只能回「没有叫「farm」的建筑」 | 「可建清单」只给了中文名，模型不知道英文 id | 清单改成 `小麦农场〔wheat_farm〕`；`Trial.resolve_id()` 再兜一层：**中文名也认**（内容里一字不差的名字），编出来的照实拒并把真 id 写在拒绝理由里 |
| `set_workers` 写成 `{"count": 3}`（schema 里叫 `value`） | 模型顺手 | `Trial` 两个键都认 |

改完之后跑通：一场 2 轮 / 8 个方案 / 25 秒，结论是**真的照沙盘说话**的 ——
比如它会拿「先盖房」那条 5 天后"住房容量 74、空房 31，可人口仍是 43、挨饿仍是 18 人"
去论证"空房填不饱肚子，先种菜"。

⚠️ 顺带一条：`deepseek-flash` 的 `content` 在 `tool_calls` 之外也会写一句话（实测 47 字），
而 `tool_calls` 优先 —— 那句话不会被丢，它会进 `assistant` 消息一起回填，下一轮它还看得见。

## 六、问话与冷却（5 天一次）

**三个入口，两个形式**（用户 2026-10）：

| 入口 | 打开 | 为什么 |
|---|---|---|
| 左侧圆钮第 6 个「预言」 | **预言页 · 全屏**（`open()`） | 面板是"翻旧卦"，和统计/科技/任务同一套全屏形式 |
| 顶栏那颗水晶球（暂停按钮左侧） | 同上（`open_for_question()`，光标进问话栏） | 游戏里想"问一句"——这里只该有村子里的东西 |
| ESC 菜单「AI 辅助设置…」 | **设置页 · 浮动对话框**（`open_settings()`） | 配置是"机器设置"，混在问话里出戏 |

页签行因此**删掉了** —— 一个入口进去只看得到一摊东西。没配好时预言页给一个「去设置」按钮
（那是唯一需要跳页的情况）。

预言页的左右分栏、历史列表怎么画，见 [town.md](town.md) §十八；这里只管契约。

用户 2026-10 定：

> "预言家 5 天才能问一次，然后点了问号以后，可以输入一行字。比如"我的食物不够了怎么办"，
> "为什么人口一直上不去"。默认这行字是"我下一步要做什么"。"

**问话那一行**（预言页左栏最下面那一行）：

- 顶栏那颗**水晶球**点开面板 → 光标直接进这一行、内容全选（默认那句已经填好，打字就换掉）
  —— **不自动发问**：用户要的是"点完可以输入一行字"。回车或点「获取瑟拉菲娜的新预言」才发。
- 每次打开都重新填回默认那句「我下一步要做什么」（上一次问过的问题不该粘在框里）。
- 写什么就原样进提示词的【殿下的问话】（见 §四），模型先答那句话再给该做的事。

**冷却 5 天**：

| 口径 | 定下来的 |
|---|---|
| 多久 | `SimCore.PROPHET_COOLDOWN_DAYS = 5`（天） |
| 从哪天起算 | 从**问到的那一天**起算：`day >= lastAskDay + 5` 才问得动 |
| 什么算"问到了" | **拿到回答才记**。失败 / 超时 / 没配 key / 点「测试连接」都**不算** —— 白等一场不该罚 5 天 |
| 存在哪 | 存档里的 **`state.prophet.lastAskDay`**（`-1` = 这一局还没问过），不是 `user://ai.cfg` |
| 历史呢 | 同一条记录里还有 **`state.prophet.log`**：`{d: 天数, q: 问话, t: 她说的原文}`，上限 30 条（面板上写 `AE 312年1月7日`，见 `docs/town.md` §三十）。只在**真的有回答**时写这个键 —— 新开局没有它，所以黄金摘要不变 |
| 为什么不放 UI 配置 | 放配置里的话：退出重进、读档、改存档都能绕开冷却；放状态里，读档也跟着回退到当时的进度 |
| 冷却期间还能用吗 | 只有「获取瑟拉菲娜的新预言」这一个按钮灰掉，上面写着「还有 N 天」。面板照常能翻历史（左栏那几条） |
| 界面上怎么显示 | 面板：按钮文字带天数（「获取新的预言（还有 5 天）」）+ 状态行「预言家在闭门静修 —— 第 N 天（还有 N 天）才回得来」。顶栏：**换灰水晶球**（`ai_assist_off.png`）+ tooltip 写第几天可用 —— 用户："必须明确告诉用户预言家是否可以用，还有多久回来" |

⚠️ **这条不参与仿真演化**：问不问都不改村子的任何数值，所以
`golden` 不受影响（黄金摘要是**按字段**取的，多一个 `prophet` 段不进摘要）。
它是整个状态里唯一一个"只记事、不演化"的段 —— 唯一的写入口是
`SimCore.mark_prophet_asked()`，由面板在**收到回答之后**调用（表现层不直接写 `s`）。

⚠️ TS 侧**只有状态字段**（`GameState.prophet` + `createInitialState`），没有冷却规则：
TS 引擎没有 UI，也就没有"问话"这个动作。字段放在两边是为了存档形状一致
（两边写出来的存档都带 `prophet`，互相读不会缺段）。这条规则的常量与实现在
`godot/scripts/sim/sim_core.gd`，门槛在 `ai_test.gd`。

## 七、配置与密钥

⚠️ **界面上只有 ESC 菜单 →「AI 辅助设置…」那一页**（用户 2026-10："过于啰嗦…这是游戏，
用户不是来学习的"）。那一页现在只有：一句引言「支持设置接入任何 OpenAI 兼容的大语言模型端点。」、
`base_url *` / `model_name *` / `api_key`（都带 placeholder）、超时 / 回复上限、保存 / 测试连接。
**别再往里加说明文字**。**预言页不看 url/model/key**（"太出戏了，破坏沉浸体验"）。

`user://ai.cfg`（Windows：`%APPDATA%\Godot\app_userdata\sovit\ai.cfg`，和存档、音量设置放一起）：

| 键 | 说明 |
|---|---|
| `base_url` | 填到 `/v1` 为止即可，程序自己接 `/chat/completions`；已经是终点也认。**默认 `https://api.deepseek.com/v1`** |
| `api_key` | **可以不填**（本地推理 ollama / llama.cpp / LM Studio / vLLM）。**没有默认值** |
| `model` | 模型名。**默认 `deepseek-flash`**（就是 DSH 这条会话在用的那个） |
| `timeout` | 秒，默认 60（多轮问话建议 120） |
| `max_tokens` | 默认 **4000**。⚠️ 别调回 800：一轮要吐 3~5 个方案的 JSON，推理模型还要先思考，800 会截在半路（见下） |
| `temperature` | 默认 0.3（要稳，同一局势给同一个答案） |

> 2026-10 去掉了 `pause_on_ask`：用户定"问的时候游戏暂停"，于是问话期间**一定**暂停，
> 不再是一个设置项（老配置文件里留着这个键会被忽略）。

- **默认值只填地址与模型名，绝不填 key**（用户 2026-10："把当前 deepseek 模型的 base_url
  和 api 填写进去"）。key 是秘密，写进代码就等于写进仓库 —— 所以 `DEFAULT_API_KEY` 这种
  东西**不存在**；key 只活在 `user://ai.cfg` 里，门槛还专门断言"默认值里不许出现像 key 的东西"。
- 代价：`is_ready()` 对新装的机器立刻为真，没填 key 就点「获取新的预言」会真的发一次注定 401 的
  请求。所以面板把 **401/403** 单独认出来，提示「像是 key 没填或不对」，比原来那句
  "还没配置"更具体（那句原来是靠空默认值兜出来的）。
- `base_url` 与 `model` 是必填的；**`api_key` 不是**（本地推理）。
- **`api_key` 只写在这个文件里**：不进仓库、不进存档、不进公告、不进日志。
  界面只显示头尾（`AiConfig.masked_key()`，例如 `sk-abc…mnop`）。
  这是明文存储（Godot 没有系统钥匙串接口）—— **别把带 key 的 user 目录传给别人**。
- 门槛 `ai_test` 把读写指到 `user://ai_test.cfg`（`AiConfig.path` 是个变量，
  和 `hud.quick_path` 同一个理由），**绝不会碰玩家自己的配置**。

## 八、失败与降级

| 情况 | 表现 |
|---|---|
| 没配 base_url / model | 点按钮提示"还没配置"并跳到「设置」页 |
| 连不上 / DNS / TLS / 超时 | 回答区显示人话（"连不上服务器（base_url 写错？网络不通？）"）+ 一句"要改地址去设置页" |
| HTTP 4xx / 5xx | 尽量把服务端的 `error.message` 原话带出来（比 "HTTP 500" 有用） |
| 200 但带 `error` / 没有 `choices` / 内容为空 | 都判失败并说明原因 |
| 回答里有 Markdown / 缺字形 | `AiClient.clean_reply()` 去掉 `**` `#` `` ` ``、行首 `- ` 换 `· `，再过 `UIKit.sanitize_text()` 换掉/丢掉像素字体没有的字 |

最后一条不是洁癖：缺字形在 Godot 里**不报错**，画出来就是个空。
门槛 `glyph_test` 管得住"代码里写的字"，**管不住运行时来的模型回答**，所以运行期再过一道。

## 九、门槛

`npm run ai:mock` + `godot verify.sh` 的 `ai` 一步（`tools/ai_test.gd`）。盯着：

| 断言 | 红了说明什么 |
|---|---|
| 跑完全套顾问（含沙盘）之后 `sim.s` **逐字节不变** | 只读契约破了 —— 黄金轨迹会漂 |
| 沙盘的命令**真的落地**（排上队或建成）、`delta` 里有 `shops` / `construction` | 方案没下进去（时间线或翻译错了） |
| 同一个方案跑两遍结果**逐位相同** | 忘了复制 rng 状态，沙盘自己变成了随机 |
| 乱下的命令被引擎拒，且 `rejected` 里说人话 | 沙盘在"假装成功"，模型会照着错的结论走 |
| `days` 夹到 5、一轮最多 5 个方案 | 上限没生效，模型能一次把 CPU 吃光 |

假服务端不只是"回一句话"，它**假装成一个会用工具的模型**：

- 请求带 `tools` → 回 `tool_calls`：第 1 轮 3 个方案、第 2 轮 2 个、第 3 轮 1 个（每轮换思路）；
- 请求**不带** `tools`（收尾轮）→ 先把前面那些 `role:"tool"` 的沙盘结果读出来，
  挑出最好的一条（先看有没有饿死人，再看人口/满意度/钱），**引用它的数字**给结论；
- 把收到的请求打出来（模型名 / 消息条数 / 提示词字节数 / 有没有带 Authorization / 有没有 tools / 已有几条沙盘结果）；

## 十一、已知取舍

- **只在 Godot 侧**（理由见开头）。TS 引擎、`src/api/server.ts` 都没有顾问接口。
- **不流式**：等整段回来一次排版（流式只会让像素字一行行跳）。
- **不做对话历史**：每次都是"规则 + 当前局势 + 这句追问"，
  不带上一轮回答 —— 局势数据包已经很大，带历史只会让 token 涨而无所得。
- **不用系统钥匙串**：`user://ai.cfg` 是明文（Godot 没有跨平台钥匙串 API）。
- **不做"AI 自动执行"**：它只出建议，绝不替玩家下单 —— 那会破坏确定性（也越权）。
- 建议里**没有"点击就直接下单"的按钮**：现在只是文字。要做的话得先想清楚
  "点一下是入队还是等次日黎明"（命令都是次日生效的）。
