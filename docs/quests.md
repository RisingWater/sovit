# 任务系统（引导系统）

> **一句话**：任务是一条**对当前村庄状态的只读判定** —— 判到了就当场完成、当场发奖，
> 不需要玩家"提交"；而且**一次只露出一层**，玩家看不到后面还有什么。
>
> **结构**：章 1–5 是**现状**（内容直接从 `content/quests.json` 抄过来，只标出要改的地方）；
> 章 6–17 是**新设计**（按 `story.md` / `characters.md` 编的）。
> **变更清单在最后（§十二）**。
>
> ⚠️ **不写年季**（2026-10-18 你定）：任务设计只按**任务链顺序** + **间隔天数**，一不看年份、二不看季节。
> 屏幕上的日期（`AE 312年1月1日`）只是显示，不驱动任何东西。

## 〇、口径

| 问题 | 定下来的口径 |
|---|---|
| 要不要玩家"提交"？ | **不要**。黎明由仿真判定，为真即完成、立即发奖 |
| 判定什么时候做？ | **每小时都判**（`stepHour` 末尾；黎明那一趟仍在 `runDawn` 末尾）+ **每条即时动作之后**再判一次。2026-10-20 用户："任务完成不用等到 6:00 吧，这样游戏体验很差" |
| 先干了、任务后出现？ | **照样算完成**；同一次黎明里会**连锁结算** |
| 奖励 | 单条 `reward`（**本版只发钱**：`reward` 仍是数字，商品那一半等 B6）；**每章**主线全绿再 **+1000 金**。支线与里程碑不挡章节奖励 |
| 显示 | **渐进显示**：`requires` 没全完成的任务**根本不下发** |
| 完成态 | 达成即结算（当场发钱、写公告），从追踪条收走；任务面板里永久留着，写「AE 312年1月9日 完成」|
| 会不会回退？ | 不会。完成过就是完成过，钱不重复发 |
| 章节间隔 | 一章主线全绿 → 领奖 → **隔 `gapDays` 天**，下一章的任务才下发。**章 1–5 = 0** |
| 里程碑 | `kind: "milestone"`：**不挡章节奖励、不发钱**，专门让追踪条不空 |
| 面板主人 | 前五章是**雷纳德**；章 5 之后归**伊莎贝拉**（她来投奔）。**面板主人 ≠ 任务发布人** |

## 六、goal 类型

| type | 判什么 | 进度怎么算 |
|---|---|---|
| `building` | 已建成 N 座 | `s["shops"]` 里同 `defId` 的条数（在途工地不算）|
| `housing` / `housing_capacity` | 某住房 N 栋 / 总容量 ≥ N | 与移民闸门同一个函数 |
| `population` / `class` | 人口 ≥ N / 某阶层 ≥ N | `residents` |
| `tech` / `tech_count` | 某科技 / 科技总数 | `research.done` |
| `good` / `produced` | 库存 ≥ N / **单日产量**曾达 N | `goods` / 台账峰值 |
| `avg_satisfaction` | 平均满意度 ≥ N | 全体算术平均 |
| `private_housing` | 私有住房 ≥ N 户 | `privateHousing` 求和 |
| `building_repaired` | 城镇中心修到某段位 | `s["townCenter"]["stage"]` |
| **`army`**（新）| 可派出的兵 ≥ N | `s["army"]["levy"]` |
| **`battle_won`**（新）| 打赢过某一仗 | `s["battleLog"]` 里有该 `place` 的胜仗 |
| **`rep`**（新）| 与某势力关系 ≥ N | `s["factions"]["rep"][id]` |
| **`gifted`**（新）| **累计送出**某商品 ≥ N | `s["gifts"][to][good]`（§四 的送物资）|

- 四个新类型要在**两份引擎 + `spec.md` §16 + 本文档**同时加
- `battle_won` 的 id 是**出击目的地**（`bandit_camp` / `bernard` / `burned_camp` / `holy_war`），中文名只出现在标题里
- `rep` 只判"≥"，不判"≤"（"某人跑了"写进剧情，不写成 goal）
- `gifted` **判的是"送出去多少"，不是"仓库里有多少"** —— 所以「送物资」这件事必须走 `gift` 命令，不能拿 `good` 糊
- 显示文案由引擎拼（`goal.text`），UI 一个字都不自己拼

### 奖励（`reward`）

两种写法都收：`1500` = `{ money: 1500 }`；新写法 `{ money?, goods? }`。`0` 与 `{}` 合法（里程碑不发钱）。
`quests.json.schemaVersion` → **3**（2026-10-20 落地：`kind` / `chapters[].gapDays` / `gifted`。
文档原先写的 4 里还有一级是 B6 的 `reward` 对象写法 —— **那一级没做**，所以现在仍是 3）。
「每章全绿再 +1000 金」这条规则不动。

## 七、面板与追踪条

- **追踪条**：固定宽 252，只显示未完成，最多 5 条，多的写「…还有 N 条」
- **空档不空**：章节间隔期间挂里程碑；里程碑也全做完时显示「眼下没有差事，先把营生做起来」
- **任务面板**：浮动对话框，左树按章分组 + 单独「里程碑」组；页签「任务」「支线」（**17 条送物资都在支线页**）
- 右栏四块：描述（`brief`）/ 要求（`goal.text`）/ 完成情况 / **完成日期**（`AE 312年1月9日`）
- **右下角立绘 = 面板主人**：前五章雷纳德，章 5 之后**伊莎贝拉**
- 默认选中第一个未完成的任务；默认只展开它所在的章
- 渐进显示照守：锁着的任务连"总数"都不参与计算
- **「交物资」类要求后面直接跟一个「提交」按钮**（用户 2026-10-20："送瑟拉菲娜礼物的任务应该直接在任务页面交，
  物资的后面加一个按钮提交"）：哪一条要求是"交 N 个某商品"，右半边就长一个按钮 —— 点一下 = 下一条 `gift` 命令
  （**即时生效**：货当场扣、任务当场结算）。按钮文案说清会发生什么：能交 →「提交 N」（N = 还差多少，最多到**未锁定**的库存）；
  没有可交的（都是被锁定的 / 没货）→ 灰着，tooltip 说还差几个。
  ⚠️ 这一档只认 `gifted`；以后再加别的"交东西"目标，扩 `panel_quest.gd::_gift_offer()` 一处即可。
- **「送物资」的另一个入口在预言面板**（瑟拉菲娜自己的面板）底部一行：选商品 + 填数量 + 「送去」，
  走同一条 `gift` 命令（§四）。两个入口并存：任务页是"照单交"，预言面板是"随手送"。

## 十二之附：被删掉的那一章，台词怎么办

旧章 6「千人之村」的章末四句（**原文**，存在 `content/quests.json` 的 `chapters[5].outro`）：

```
殿下，国王陛下的旨意到了。
三年之期未满，您的领地已是七子之首。
陛下说——
他选对了人。
```

这四句在新剧情里**不可能发生**（父王死在宣布之前），处理办法是**拆成两半**、不浪费：

| 原句 | 新位置 | 变成 |
|---|---|---|
| （新写）| **章 6 章首 · 雷纳德** | 「陛下本来是要在这一天说一句话的。」「他没能说。」|
| 「他选对了人。」的味道 | **章 17 章末 · 伊莲娜** | 「现在轮到您自己说了。」|
| 其余两句（"旨意到了""七子之首"）| — | **弃用**：它们的前提（父王能开口、考期已满）已经不存在 |

> 所以删章 6 时，**`chapters[5].outro` 整段删掉**是对的；但删之前把原文记在这里，
> 免得以后有人以为"这几句是被误删的"。
